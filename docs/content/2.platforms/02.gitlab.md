## Address it

```ts
import { createProvider } from "@agntn/forges";

const gitlab = await createProvider("gitlab"); // GITLAB_TOKEN, GL_TOKEN, GITLAB_PAT, then glab
const selfHosted = await createProvider("gitlab", {
  token: "glpat-…",
  baseURL: "https://gitlab.example.com",
});
```

`/api/v4` is added when the base URL lacks it. The token travels in `Private-Token`.

## What it reads

| Resource             | Endpoint                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| repos                | `GET /projects/:id`, `GET /users/:owner/projects`, `GET /groups/:owner/projects` on 404                                             |
| issues               | `GET /projects/:id/issues`, `…/issues?search=`, `POST /projects/:id/issues`, `PUT …/issues/:iid`, `…/issues/:iid/notes`             |
| merge requests       | `GET /projects/:id/merge_requests`, `…/merge_requests/:iid/diffs`, `…/merge_requests/:iid/pipelines`, `…/merge_requests/:iid/notes` |
| merge request search | `GET /merge_requests?scope=all`, `GET /groups/:id/merge_requests`, `GET /projects/:id/merge_requests` with `search`                 |
| merge request edits  | `PUT /projects/:id/merge_requests/:iid`, after a read when assignees change                                                         |
| commits              | `GET /projects/:id/repository/commits`, `…/commits/:sha`, `…/commits/:sha/diff`                                                     |
| CI runs              | `GET /projects/:id/pipelines`, `…/pipelines/:pipeline_id`, `…/pipelines/:pipeline_id/jobs`, `…/jobs/:job_id/trace`                  |
| releases             | `GET /projects/:id/releases`, `…/releases/:tag_name`, `POST …/releases`, `PUT …/releases/:tag_name`                                 |
| threads              | `GET /projects/:id/merge_requests/:iid/discussions`, `PUT …/discussions/:id`                                                        |
| templates            | `GET /projects/:id/templates/issues`, `…/templates/merge_requests`                                                                  |
| code                 | `GET /search`, `GET /groups/:id/search`, `GET /projects/:id/search` with `scope=blobs`                                              |
| commit search        | `GET /search`, `GET /groups/:id/search`, `GET /projects/:id/search` with `scope=commits`                                            |

`owner/repo` becomes a project id once and is cached per provider (`gitlab.projectIdCacheMax`, `gitlab.projectIdCacheTtl` in the config). Pagination reads `x-next-page`.

## What comes back

`number` is the `iid`, never the global `id`. `viewerPermission` takes the higher of your project and group access: Guest is `read`, Planner and Reporter are `triage`, Developer is `write`, Maintainer is `maintain` and Owner is `admin`. `Thread.isOutdated` is always `false`, the API has no such flag. Changed files of a merge request carry `null` counts when the diff is collapsed or oversized. Commit reads take at most 10 000 diff rows per call and `filesComplete` is `null` past that.

`listComments` asks for notes with an explicit ascending sort and drops two kinds: system notes about label and state churn, and inline `DiffNote`s, which are threads. So a short page with `hasNextPage: true` is normal, keep paging.

Templates come from the effective template API, group and instance inheritance already applied. When the API hides the winning source, `scope` is `unknown` and the source fields are `null`.

## Gotchas

- Discussions answer 401 without a token, even on a public project. Repositories, issues, merge requests, commits and pipelines read fine anonymously. Discussions do not, and I did not expect that either.
- Every search call needs a token. Global and group code search also need Premium or Ultimate with advanced or exact code search on, and global and group commit search need advanced search. Project search does not. Commit search in a project reads the default branch only.
- `/users/:owner/projects` is a 404 for a group. `repos.list` falls back to `/groups/:owner/projects` on that status only.
- Search qualifiers are plain text. `label:bug` searches for the string `label:bug`.
- `pullRequests.searchGlobal` needs no token, but across all of gitlab.com a keyword search can hit GitLab's 408 after about 15 seconds. An `owner` group or an `author` narrows it enough.
- A merged results or merge train pipeline has the SHA of a merge commit GitLab builds, not the head SHA, and the API does not say which head it was built from. `listChecks` keeps the one the merge request names as `head_pipeline`, which GitLab moves only once a pipeline for a new head exists, so right after a push it can still be the previous head's pipeline.
- The merge request pipeline rows have no `name`, only `GET /projects/:id/pipelines/:pipeline_id` has it, so `listChecks` reads each pipeline on the page once more, from the project it ran in, on every call, because the metadata endpoint can rename a pipeline. A fork merge request runs in the fork, and the target project answers 404 for that pipeline. A name lookup that fails keeps its row, named `pipeline`, with a warning on stderr.
- GitLab Free takes one assignee. Two are rejected before the request.
- Releases have no id, no draft and no pre-release. `Release.id` is the tag, both flags are `false`, and asking for either on a create or update is a 501 rather than a release that goes public unasked.
- `users.get` costs two requests: the username search returns a stub, the id from it reads the full profile.
