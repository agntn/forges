## Thirty-six tools, three surfaces

The MCP server, the Pi extension and the OMP extension all call the same executors in `src/tool-operations.ts`, so they answer identically. Fix one, fixed everywhere. The hosted tools mirror the ten resources; local merge verification reads a checkout:

| Group                  | Tools                                                                                                                                                                                                                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| repositories           | `forges_repos_list`, `forges_repos_get`                                                                                                                                                                                                                                                  |
| contribution templates | `forges_contribution_templates_list`, `forges_contribution_templates_get`                                                                                                                                                                                                                |
| code                   | `forges_code_search`                                                                                                                                                                                                                                                                     |
| CI and commits         | `forges_ci_runs_list`, `forges_commits_list`, `forges_commits_get`                                                                                                                                                                                                                       |
| releases               | `forges_releases_list`, `forges_releases_get`, `forges_releases_create`, `forges_releases_update`                                                                                                                                                                                        |
| issues                 | `forges_issues_list`, `forges_issues_search`, `forges_issues_get`, `forges_issues_comments`, `forges_issues_comments_get`, `forges_issues_create`                                                                                                                                        |
| pull requests          | `forges_pull_requests_list`, `forges_pull_requests_search`, `forges_pull_requests_get`, `forges_pull_requests_files`, `forges_pull_requests_checks`, `forges_pull_requests_reviews`, `forges_pull_requests_comments`, `forges_pull_requests_comments_get`, `forges_pull_requests_create` |
| users and auth         | `forges_users_get`, `forges_users_authenticated`, `forges_auth_reload`                                                                                                                                                                                                                   |
| review threads         | `forges_threads_list`, `forges_threads_get`, `forges_threads_reply`, `forges_threads_resolve`, `forges_threads_unresolve`                                                                                                                                                                |
| local inspection       | `forges_local_inspect`                                                                                                                                                                                                                                                                   |
| local Git              | `forges_local_merge_verify`                                                                                                                                                                                                                                                              |

Every hosted tool takes a `platform` of `github`, `gitlab` or `gitea` plus the owner, repo, number, tag or username the call needs.

## Local inspection

`forges_local_inspect` returns local status, tracked files and recent HEAD commit messages, including bodies. Pass `cwd`, optional `paths` (Git pathspecs relative to the repository root) and `historyLimit` (1-100, default 3). For example, `paths: ["*AGENTS.md"]` finds tracked instruction files; `:(literal)` treats wildcard characters literally. Omit `paths` to inspect the whole repository. The library entry is `inspectLocal` from `@agntn/forges/local`.

Status keeps the index and worktree columns separate, including untracked files and rename source paths. An unborn branch returns `headSha: null` and no commits. Nothing is fetched or written, but concurrent edits can change the checkout between reads. Each Git command has a 10 second timeout and a 1 MiB output cap; exceeding either fails the call rather than returning an apparently complete subset. Git must be on `PATH` and support both `--no-lazy-fetch` and `ls-files --deduplicate`.

## Local merge verification

`forges_local_merge_verify` takes `cwd`, `head`, `mergeCommit`, `target` and `paths`. It runs Git locally, needs no platform credentials and returns `platform: "local"`. Fetch the target first, then pass the forge's merge or squash commit and the PR head. The library entry is `verifyLocalMerge` from `@agntn/forges/local`.

The result pins all three resolved SHAs. `mergeReachable` checks the merge commit against the target's local history; `pathsMatch` compares the head and merge trees, including file modes. Paths are literal and relative to the checkout root, even when `cwd` is a subdirectory. Supply 1 to 100 files or directories. Each must exist in the head tree, merge tree or the merge commit's first parent, so a file deleted from both compared trees can still be checked. In a shallow checkout, fetch that parent before checking such deletions. Globs aren't expanded.

No fetch, checkout, reset, branch deletion or credential change happens here. Inherited `GIT_*` variables can't redirect the checkout, replacement objects are disabled, and diffs don't run external drivers or text conversion. Each Git command has a ten-second timeout and a 1 MiB output limit. Invalid refs, absent paths and command failures throw rather than returning false.

A match isn't a cleanup verdict. Omitted paths aren't checked, a shallow checkout may lack ancestry, and refs can move after the read. Confirm the live PR and local worktree state before any cleanup; this tool doesn't do that for the caller.

## MCP

```bash
forges mcp
claude mcp add forges --scope user -- npx -y @agntn/forges mcp
```

Or in a client's config:

```json
{
  "mcpServers": {
    "forges": { "command": "npx", "args": ["-y", "@agntn/forges", "mcp"] }
  }
}
```

The server speaks MCP over stdio. `createMcpServer()` from `@agntn/forges/mcp` returns the same server for a host that brings its own transport.

An MCP client sees the text a tool returns and nothing else, so the text carries the whole answer as JSON. Lists and searches drop bodies and name the tool that reads one in full. One page of a busy repository with bodies is big enough to push the conversation that asked for it out of the window, and I would rather the model asks twice. Pull request search leaves revision details to `forges_pull_requests_get`. `forges_threads_list` bounds each comment to twelve lines and four thousand characters but keeps every comment of every thread on the page, so ask for a small `perPage` on a heavily reviewed pull request. The comment tools carry the same bound, and their `_get` variants read one comment whole.

## Reads, writes and credentials

Hosted read tools use the normal [token chain](/guide/auth) and fall back to anonymous access when nothing is found. Anonymous providers are kept apart and can never be reused for a write, not even by accident.

Seven tools write: `forges_issues_create`, `forges_pull_requests_create`, `forges_releases_create`, `forges_releases_update`, `forges_threads_reply`, `forges_threads_resolve` and `forges_threads_unresolve`. They carry MCP annotations saying so, `readOnlyHint: false`. The three creates and the reply are marked as not idempotent because doing them twice leaves two of them behind. Resolve, unresolve and the release update are idempotent, and the release update is the one tool marked destructive, because the title and notes it replaces are gone. `forges_users_authenticated` names the account the writes would go out as, check it before you let a model write anything.

The credential stays pinned per platform and endpoint until `forges_auth_reload` swaps it and returns the new profile. Reload is gated as a mutation because it changes local server state. It writes nothing to the platform.

## Hosts stay local

A self hosted endpoint is `FORGES_GITHUB_BASE_URL`, `FORGES_GITLAB_BASE_URL` or `FORGES_GITEA_BASE_URL` in the agent's process environment. Never a tool argument, so a model cannot aim a call at another host. A failure names the status and, on a rate limit, the retry window. It never repeats the endpoint, so the host stays out of the model's context even when the platform answers with an error.

A failed operation is a tool error, not a transport failure: unknown repository, rejected token, exhausted rate limit. The model sees a sentence, the session survives.

## Pi and OMP

```bash
pi install npm:@agntn/forges
```

The package declares both extensions in `package.json`. They render tool calls and results in the terminal: a repository row, a list of pull requests with their states, a thread with its comments, bounded the same way the MCP text is. In Pi, `forges_pull_requests_create`, `forges_releases_create` and `forges_releases_update` show what they are about to send and wait for a confirmation, and refuse to run without a UI to ask. `forges_repos_get` includes fork state, the parent and the viewer's role. A `null` role means the platform said nothing, not that the viewer has no access.

## What the answer is

The tools return the normalized objects, not prose. The [Explorer](/explorer) shows the same objects for any public repository, a quick way to check a model's summary against the source when it gets creative.

::caution
Issue bodies, comments and review threads are written by whoever has an account on the platform. Data to report, not instructions to follow. An agent that reads `body: "ignore previous instructions"` has learned one thing about the issue and nothing about what to do next.
::
